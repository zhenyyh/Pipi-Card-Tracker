# 客户端口径考证：把「靠猜」的地方换成「官方说法」

这份文档回答一个问题：**我们采牌局数据时，哪些地方在猜，能不能不猜。**

办法是直接拆 APK（`D:\Python学习\phz-monitor\_apk`），从客户端自己的
字节码和随包资源里找到答案，而不是在运行时反复试字段。

结论先摆：**六个明牌数组、20 张「卡牌」、坎、将、胡息对账口径，全部有出处。**
剩下的不确定项在最后一节，都标了「怎么才能定」。

## 0. 方法：怎么把 `.jsc` 里的字符串捞出来

`assets/` 下 471 个 `.jsc` 不是明文 JS，是 **SpiderMonkey XDR 字节码**。
`tools/jsc_strings.py` 按实测格式精确提取，不靠正则乱扫。

格式（逐条对过字节，不是猜）：

```
文件头 4 字节  2C C0 73 B9            XDR 魔数，版本 0xB9
每个字符串原子：
    uint32 v      小端；v == 2 × 字符数 + 1   ← 最低位是「这是字符串」标志，不是长度
    char   s[n]   n = (v - 1) / 2，UTF-8，★ 没有 NUL 收尾，后面紧接字节码
```

实测校验：

| 字节 | v | n | 内容 | 紧跟的下一字节 |
|---|---|---|---|---|
| `15 00 00 00` | 0x15 = 21 | 10 | `getKingNum` | `1D`（不是 0） |
| `0B 00 00 00` | 0x0B = 11 | 5 | `isRed` | — |
| `19 00 00 00` | 0x19 = 25 | 12 | `kingHuMatrix` | — |
| `1F 00 00 00` | 0x1F = 31 | 15 | `allChiFlagArray` | — |

**踩过的三个坑**（写下来免得再踩）：

1. 以为「uint32 长度 + 字符串 + NUL」→ 只捞到 2 条。
2. 以为「NUL 结尾的可打印串」→ 属性名和字节码粘成 `playType#` 这种垃圾。
3. 以为「2n+1 + n 字节 + NUL」→ 只捞到 106 条，漏 90%。
4. ✅ 正确：**奇数 == 2n+1，n 字节，无 NUL。**

工具用法：

```bash
python tools/jsc_strings.py <某个.jsc>                     # 全部原子
python tools/jsc_strings.py <某个.jsc> --grep gang -C 4    # 命中项带邻居
python tools/jsc_strings.py --dir <assets> --field-map     # 字段使用矩阵
python tools/jsc_strings.py --dir <assets> --stats         # 每个文件多少原子
```

全量统计：**471 个 `.jsc`，213 746 个字符串原子。**

## 1. 第一条硬事实：客户端代码里**一个汉字都没有**

拿 `[\u4e00-\u9fff]` 扫全部 213 746 个原子 → **0 命中**。

⇒ **别在 `.jsc` 里找中文标签。** 结算上那些「十红」「自摸」「将」「坎」，
是**服务端下发的字符串**（`roundEnd.players[uid].mjdesc` 是字符串数组）

不是搜法不对，是它压根不在代码里。

## 2. 明牌：客户端把六个数组分开存，来源信息是白送的

以前最折磨人的是「提 / 跑」「碰 / 偎」分不清 —— 因为收包事件只给
`MJGang {card, gang, from}`，要靠 `from == 自己` 反推，`gang` 还是个
牌型编码（1/2/4/6）不是张数。

**客户端自己根本不这么算。** `jsclient.data.sData.players[uid]` 上是
**六个独立数组**，一个数组就是一种牌型：

| 数组 | 牌型 | 张数 | 来源 | 息（大/小） |
|---|---|---|---|---|
| `mjpeng`  | 碰 | 3 | 别人打的 | 3 / 1 |
| `mjpeng1` | 偎 | 3 | 自己摸的第 3 张 | 6 / 3 |
| `mjgang0` | 提 | 4 | 4 张全在手 | 12 / 9 |
| `mjgang1` | 跑 | 4 | 3 张 + 别人打的第 4 张 | 9 / 6 |
| `mjchi`   | 吃 / **绞牌** | 3 | 顺子，或「一对 + 一张同点异大小写」 | 特殊顺 6 / 3，绞 0 |
| `mjlie`   | 摆火 | 1 | 吃牌时手里同样的牌摊出来 | **0** |

★ **`mjchi` 里装的是两种东西**：一句话（顺子）和**绞牌**。邵阳规则第 8 条
「…与自己手中的牌组合成 1 句话，**或者绞牌**，放到桌面，称为吃牌」——
所以绞牌也走 `mjchi`。实测座位0 的 `mjchi = [5, 105, 105]` 就是
「一对伍 + 一张五」的绞牌，不是顺子。以前把它当「认不出」，会把 3 张牌白白丢掉。
绞牌是合法门子但 **0 胡息**。

### 证据（客户端自己的函数名，不是我推断的）

`phzApp.jsc` 里 `wei`（偎）操作的字节码原子序列：

```
playEffect | wei | mjpeng1 | push | SelfUid | spliceHandCard2 | MJGang1_1 | MJGang1_2 | ...
        ↑          ↑
     偎的特效    推进 mjpeng1          ← 偎 → mjpeng1，写死的
```

`pao`（跑）操作：

```
... spliceHandCard2 | MJGang1_1 | MJGang1_2 | MJGang8_1 | MJGang8_2 | MJGang8_3
  | mjgang0 | mjgang1 | nv/chongpao | pao | mjpeng | splice | indexOf | YQPH
                          ↑                    ↑
                       跑到 mjgang1        跑要从 mjpeng(碰) 升级
```

`CommonPlay.jsc` 的摆牌渲染函数里，局部变量名直接照抄数组名：

```
... AddNewCard | up | peng | mjpengFrom | indexOf | mjpeng1 | YZ_LDS | peng1
  | mjlie | down | tag | mjgang0 | gang0 | isgang4 | mjgang1 | ... | gang1
                          ↑                                        ↑
                    peng / peng1 成对                         gang0 / gang1 成对
```

`isgang4` 紧跟在 `gang0` 后面 —— 这是「4 张的那个提」的标记。
**`gang0`/`gang1` 的 0/1 后缀不是张数，是「提/跑」的区分位**，
和 `peng`/`peng1` 完全同构。`MJGang.gang` 那套 1/2/4/6 编码是**另一回事**
（收包时的牌型编码），跟数组无关。

### `mjlie`（摆火）—— 以前完全没算，是守恒的隐形漏洞

`help.txt` 第 10 条：

> **摆火**：当吃的牌手中还有时，必须要将手中的这张牌根据某种组合，
> 也要放到桌面，称为摆火。

摆火是**单张**、**不计息**，但**它占牌数**。上一版守恒只算
`peng/peng1/gang0/gang1/chi`，一旦出现摆火，总牌守恒必然缺牌。
现在 `meld_from_array("lie", …)` 会把每张单独入账（`xi = 0`），
守恒才对得上。

`CommonPlay.jsc` 的 `isBkb()` 里 `isHaveThree` 查 `mjpeng`、`isHaveTwo` 查
`mjpeng1` —— 就是判断「吃/绞之后手里还有没有能配套的牌」，有就必须摆。

### `from` 是座位号，不是 uid

`MJPeng / MJChi / MJGang` 里的 `from` 是**座位号（0/1）**。而且：

```
from == 自己座位  ⇒  用的是「自己摸的那张牌」（自己吃自己 / 偎）
                      这张牌不消耗任何人的弃牌堆
from == 对方座位  ⇒  接别人打的，那张牌从对方弃牌堆消失
```

邵阳规则第 8 条允许「自己摸的牌示众后没人碰、可以自己吃」。实测这一局：

```
MJChi  uid=5513337 [5,105,105] from=0   ← 座位0 自己吃自己摸的 五
MJChi  uid=5519304 [2,7,10]    from=1   ← 座位1 自己吃自己摸的
MJChi  uid=5519304 [6,8,7]     from=1   ← 同上
MJPeng uid=5519304 card=108    from=0   ← 真·接座位0 打的
```

⇒ **不能拿 `from != 自己` 当「这组牌消耗了弃牌」的判据去剪弃牌堆**，
只有 `from != 自己` 的那些才会从弃牌堆消失。

`KAN_XI = {大: 6, 小: 3}`。同一局的「7 方门子」也正好：明牌 3 组 + 手牌 4 方。

★ 顺带把**特殊顺的胡息**也钉死了：help.txt 第 15 条原话是

以前一张表不分大小写一律给 6 是错的 —— 这一局的小字「二七十」必须算 3 才对得上 21。

### 3.6 `choupai = 20` 仍然只能靠邵阳剥皮那条解释

实测 `playerNum = 2`、`initHandNum = 20`、`choupai = 20`。

`邵阳剥皮.txt` 第 27 条：

`choupai = 20` 就是这 20 张，**这是这个字段名的真正含义** ——

## 4. 「卡 20 张」把守恒公式彻底解释了

以前这个公式是**试出来的**：

```
80 - choupai = 各家手牌 + 弃牌堆 + 明牌 + 墩剩
```

现在知道为什么：

```
本局牌池 = 80 - choupai            (二人精简抽掉 20 → 池 = 60)
发牌     = initHandNum × playerNum (20 × 2 = 40)
墩       = 池 - 40 = 20
墩剩     = 池 - cardNext           ← cardNext 就是池内已发到的游标
```

`cardNext` 是**池内下标**，不是 80 张里的下标。逐局实证：

| 局 | choupai | pool | cardNext | 墩剩 = pool - cardNext | 在场 | 合计 |
|---|---|---|---|---|---|---|
| round2 | 20 | 60 | 58 | 2 | 58 | 60 ✓ |
| round5 | 20 | 60 | 48 | 12 | 48 | 60 ✓ |
| round_kan | 20 | 60 | 55 | 5 | **56** | **61 ✗** |
| multi4 第4局 | 20 | 60 | 53 | 7 | 53 | 60 ✓ |

### ★ 长期「多 1 张」的真因：待反应的牌没从弃牌堆里剪掉

`newCard.mjput` 快照会混进一张**别人刚打出、正等自己反应**的牌。以前 `drop_pending()`
只剪「出牌时序」，**没剪弃牌堆**，于是那张「其实已经被拿走」的牌一直留在某人堆里，
稳定多 1 张。

multi4 第 4 局是干净的样本：

```
座0 弃牌堆 = [8, 2, 106, 4, 7, 103, 109]   ← 末尾这张 109
tData.lastPut = 109，lastPutPlayer = 1（座1）
109 是座1 胡走的那张，服务端快照拍在移除之前
```

剪掉后：座0 手7+弃6+明13 = 26，座1 手9+弃6+明12 = 27，合计 **53 + 7 = 60 ✓**

判据照旧：**`lastPut` 出现在「非 `lastPutPlayer`」的弃牌堆里** ⇒ 那张已经易主。
自己打出去的那张（`st == lastPutPlayer`）**不能剪**，它本来就该留在自己堆里。

剪完两个有 live 快照的局都平了；`round_kan` 仍是 61，它是**旧房间**（`tableid=812760`）
的残留数据，且 live 与事件两个来源的张数本身对不齐，先按「采集限制」挂着（见第 9 节）。

> 曾试过「自摸局 `cardNext` 少算 1 张 ⇒ 墩剩 −1」去凑 round_kan，被 `round_v3` 直接
> 打掉：它同样 `lastDrawPlayer == winner`（自摸），但 `cardNext` 是准的。**别再试这条路。**

## 5. 胡息对账：以前只算了一半，这才是真凶

老问题：round2 明牌自算 11 胡，游戏 `origWinNum = 20`，差 9。
一度怀疑是坎，其实是**我们只算了明牌那一半**。

`help.txt` 第 20 条（胡牌条件）：

> **手里的与桌面上的牌组合有 7 方门子。**

7 方门子 = 明牌组数 + **手牌拆出来的门子数**。手牌里的三类东西只能自己算：

| 手牌门子 | 判据 | 胡息 |
|---|---|---|
| 坎 | 3 张同值**同大小写**，起手就在手上 | 大 6 / 小 3（**已实测确认计息**） |
| 顺子 | 3 张同大小写连号；另加 贰柒拾 / 壹贰叁 | 特殊顺 大 6 / 小 3，普通 0 |
| 绞牌 | 一对 + 一张同点异大小写（`mjchi` 里也是这个） | 0 |
| 将 | 一对牌 | **0** |

**「将」终于有定义了**（`help.txt` 第 17 条）：

> 一方门子：一句话，一绞牌，一碰，一提，一偎，一跑都称为 1 方门子。
> **当有跑牌或提牌时，一对牌可以称为 1 方门子，叫做将**，
> 跑牌或提牌时，必须有一对将，否则就要掉将。

⇒ **「将」不是牌型、不产生胡息，它是「已有跑/提时的那第 7 方门子」。**
所以它永远不该出现在胡息计算里，只影响「够不够 7 方」。

### 现在的对账结果（`python -m pct replay`）

| 局 | 明牌 | 手牌 | 合计 | origWinNum | 明牌组 + 手牌方 |
|---|---|---|---|---|---|
| round5（`round_v3`） | 18 | 0 | **18** ✓ | 18 | 4 + 3 = 7 ✓ |
| round_kan（有坎） | 6 | 15 | **21** ✓ | 21 | 3 + 4 = 7 ✓ |
| multi4 第1局（同 round_kan） | 6 | 15 | **21** ✓ | 21 | 3 + 4 = 7 ✓ |
| multi4 第4局（接炮） | 6 | 9 | **15** ✓ | 15 | 4 + 3 = 7 ✓ |

round5 手牌 8 张拆成：顺 `柒捌玖`（0）+ 绞 `八八捌`（0）+ 将 `二二`（0）。
那局能对上纯属巧合 —— 手牌恰好零息。**凡手牌有坎或特殊顺的局，旧算法必然少算。**
round_kan 就是反例：手牌 15 胡，不拆手牌只能算到 6。

### ★ 最后差的那 3 息：手上的「坎」还是「碰」，看第 3 张是谁给的

multi4 第 4 局长期算不平：明牌 6、手牌 12，合计 18，而 `origWinNum = 15`，差 3。

试过又否证的两条：

| 假设 | 结果 |
|---|---|
| 小字「一二三」明牌吃不产生胡息 | ✗ 被 `round_v3` 打掉 —— 它明牌吃**大字**`壹贰叁`计 6，`origWinNum` 18 精确对上 |
| 坎一律按小字 3 计 | ✗ 被 `round_kan` 打掉 —— 坎拾 6 + 坎一 3 是 21 的唯一解 |
| `limitScore=15` 是胡息封顶 | ✗ 第 1 局 orig=21 > 15 |

真因在手牌来源。手牌 9 张是 `[109,101,8,109,101,101,7,9,109]`：

```
101 × 3  壹壹壹   自己摸齐 → 坎  大 6
7 8 9    七八九   普通顺      →  0
109 × 3  玖玖玖   ★ 其中一张是别人打的 → 碰  大 3
                  （不是坎，坎要 6）
```

判据就在结算里：`tData.lastPut = 109`，而 `tData.lastDrawPlayer = 0` ≠ `winner(1)`
⇒ 这是**接炮**，最后那张 109 是座上家打出来的。**胡牌瞬间的 `mjhand` 含刚胡进来的
那张**，所以它和手上两张凑成的只能是「碰」。

`help.txt` 第 4 条本来就这么写：

> 碰牌：当别人打或摸的牌自己手中有一对，则可以碰牌。

⇒ **`split_hand` 必须有「这张牌来自别人」的输入**，否则一律按坎算，多算 3 息。
实现成 `hand_xi(hand, foreign={lastPut})`，只在**非自摸**时传（自摸的人最后一张是自己
摸的，凑成坎是合法的，传了反而错）。

自摸判据用 **`lastDrawPlayer == winner`**，不要看 `mjdesc` 里有没有「自摸」——
那是名堂列表，接炮的局它是空的，但同样为空的局也可能是别的原因。

| 局 | lastPut | 自摸 | lastPut 在赢家手上出现 | 处理 |
|---|---|---|---|---|
| round_v3 | 110 | 是 | 0 次 | 不受影响 |
| round_kan | 5 | 是 | 1 次（在三四五里） | 不受影响 |
| multi4 第4局 | 109 | **否** | **3 次** | 降级为碰 −3 |

这一条同时解释了为什么它只在「接炮 + 手上恰有一对同值」时才冒出来 —— 三个条件同时
成立才会踩到，所以前几局一直没暴露。

### `winNum` 和 `origWinNum` 的关系：名堂**乘算**（四局实证）

```
winNum = origWinNum × 名堂倍率        （倍率之间也是乘，不是加）
```

| 局 | origWinNum | 红字张数 | 自摸 | 名堂 | 倍率 | winNum |
|---|---|---|---|---|---|---|
| round_kan | 21 | 8 | 是 | 自摸 | ×2 | **42** ✓ |
| multi4 第1局 | 21 | 8 | 是 | 自摸 | ×2 | **42** ✓ |
| multi4 第4局 | 15 | 3 | 否（放炮） | 放炮 | ×1 | **15** ✓ |
| round_v3 | 18 | **11** | 是 | **十红**（红胡）· 自摸 | **×4** | **72** ✓ |

★ 「十红」就是线上规则页里的**红胡**（`10 ≤ 红字 < 13` → 胡息翻倍）。
18 × 2（红胡）× 2（自摸）= 72，**乘算才对得上**；加法（邵阳的 +10）会得到 46 或 38。

判据完全用**自己的牌**算，不看 `mjdesc` 字符串：

```
红字张数 = 该玩家明牌 + 终局手牌里的二七十/贰柒拾张数
固定 100 胡息：红 ≥ 13（二人/三人；四人 ≥ 8）→ 十三红
              红 = 0                          → 乌胡
              裸胡息 = 30                     → 三十胡
翻倍（乘算）：10 ≤ 红 < 13 → 红胡   红 = 1 → 一点红
              裸胡息 = 20   → 卡胡   自摸   → 自摸
顺序：先判固定 100，命中就不再乘（它们本身就是「算 100」）
```

⇒ **这是第二个对账锚点**：`xi_total == origWinNum` 只证明「门子算对了」，
`fan_win(...) == winNum` 才证明「整局的胡息和名堂都读懂了」。现在两条同时要求。

`tData` 里跟倍数相关的开关全都关着：`fanType=0`、`multipleNum=0`、
`multipleRule=0`、`xingCard=-1`、`xingNum=0`、`caiPaiArr` 全 0、`qiduidaikan=false`、
`showWei=false`、`hzLimit=false`。⇒ 倍率只来自名堂，`multiple` 字段恒为 1。

**还没实现的三个名堂**（数据里没出现过，实现里遇到会判不一致而不是瞎猜）：
一块匾（只有一门红字且全红字，翻倍）、海底胡（所胡的牌是墩里最后一张，翻倍）、
天胡/地胡（各 100 胡息，需要「第几手」信息，`tData` 里没有）。

## 8. 采集侧的三条硬约束（跟口径无关，但会让人以为口径错了）

1. **`evalString` 只返回 bool。** JS 必须自己
   `jsb.fileUtils.writeStringToFile(content, path)` 落盘。
2. **agent 用「`lastResult()` 返回值有没有变」判断脚本跑完了。**
   内容完全相同会被当成「没执行」，5 秒超时且不拷输出。
   ⇒ **每个采集脚本的 `return` 必须带 `Date.now()`。**
3. **别自己拼 `su -mm -c '...'` 交给 `adb shell`** —— adb 会吃掉外层引号。
   用 `Bridge` 里的封装。

另外：`flow3 --mode clear` / `pct clear` 会**顺带卸钩**。
开新一轮之前不要随手 clear，否则一整局采不到事件（这个坑踩过，
表现为「又打了一局但 0 事件」）。

## 10. 一页速查

```
牌值   组别×100 + 点数   1..10 小写 / 101..110 大写   六显示为「陸」
红张   二七十，大小写都红：[2,7,10,102,107,110]        24 张 / 80
牌池   80 - choupai        本房间 choupai=20 → 池 60
发牌   initHandNum × playerNum = 20 × 2 = 40
墩     池 - 发牌 = 20      墩剩 = 池 - cardNext
守恒   手牌 + 弃牌 + 明牌 + 墩剩 = 池
       弃牌堆要剪掉「lastPut 出现在非 lastPutPlayer 堆里」的那张（已易主）
明牌   mjpeng 碰 / mjpeng1 偎 / mjgang0 提 / mjgang1 跑
       mjchi 吃 + 绞 / mjlie 摆火
胡息   提 12/9  跑 9/6  偎 6/3  碰 3/1  坎 6/3
       特殊顺（壹贰叁/贰柒拾）大 6 / 小 3   普通顺 0   绞 0   将 0
       ★ 手上 3 张同值：自己摸齐 = 坎(6/3)；第 3 张来自别人 = 碰(3/1)
         判据 lastPut ∈ mjhand 且 lastDrawPlayer != winner（接炮）
对账   ① 明牌息 + 手牌门子息 == origWinNum
       ② origWinNum × 名堂倍率 == winNum        ← 两个都要过
门子   明牌组数 + 手牌组数 == 7 才能胡（特殊 3 提 5 坎例外）
名堂   固定 100：红≥13 十三红 / 红=0 乌胡 / 胡息=30 三十胡
       翻倍（乘算）：10≤红<13 红胡 / 红=1 一点红 / 胡息=20 卡胡 / 自摸
       放炮不翻倍
玩法   huziType=2 == 娄底放炮罚（起胡 15 胡）；邵阳剥皮是 10 胡
       两套胡息表一样，差别在名堂：邵阳 +10 加法，娄底 ×2 乘法
from   MJChi/MJPeng/MJGang 的 from 是**座位号**；
       from == 自己 ⇒ 自己摸的牌自己吃/偎，不消耗弃牌堆
自摸   lastDrawPlayer == winner（别用 mjdesc 里有没有「自摸」）
```

★ 胡息表里的「大/小」是**大字/小字**（壹贰叁 = 大，一二三 = 小），不是大小顺序。
